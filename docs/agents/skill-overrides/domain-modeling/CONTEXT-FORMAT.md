# CONTEXT.md format

Keep the root CONTEXT.md as a domain glossary. Group related terms under natural headings. Define each term in one or two sentences and list misleading alternatives under `_Avoid_`. Include domain concepts, not general programming concepts or implementation decisions. Resolve ambiguity before updating a term. Implementation tradeoffs belong in an ADR when they meet the skill's threshold.

This repo has one existing context; preserve that layout unless the user approves a domain split.
